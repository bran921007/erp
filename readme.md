# ERP

Runs on PHP 8.2+ and maintained Laravel 12. Install with `composer install`, copy `.env.example` to `.env`, configure the existing database and run `php artisan key:generate`. Serve only `public/`. Composer installs into `vendor-runtime/`; all entrypoints use it. The tracked `vendor/` is an inactive historical snapshot and must not be served or loaded.

Routes, model tables, field names and business calculations are retained. Modern Laravel handles sessions, authentication and CSRF; the login page sends the CSRF token and Angular uses Laravel's XSRF cookie. Existing database rows and migration history must be preserved. New installations no longer seed sample people or public default passwords; the `casual` walk-in customer remains. Provision users explicitly. Set `SESSION_SECURE_COOKIE=false` only for local HTTP.

The existing browser forms omit dates for products, suppliers, orders, details and purchases. Apply the additive `2026_10_22_000000_allow_unknown_form_dates` migration with `php artisan migrate`: omitted dates now remain unknown (`NULL`), instead of relying on MySQL's historical zero-date coercion. Existing dates, including historical zero dates, are retained; no current dates are fabricated. Fields that the forms omit retain their old empty-string/zero defaults, and explicitly supplied values are preserved. Strict SQL mode remains enabled. The date migration's rollback checks every affected table before altering any schema and refuses while unknown dates remain; reconcile those dates explicitly before rolling back.

Run `composer test` for HTTP login/logout, dashboard, CRUD, inventory, order and purchase flows and migrations against in-memory SQLite. The real browser payloads, explicit values, preservation of existing valid/zero dates and safe rollback are covered. For an isolated MySQL test database, set `DB_CONNECTION=mysql` and the synthetic connection variables plus `REQUIRE_STRICT_MYSQL=1` to verify the actual driver and strict session mode. Never run `migrate:fresh` on an existing application database. Before deployment plan the application key/session cutover from Laravel 4. No deployment or production database operation is included.
